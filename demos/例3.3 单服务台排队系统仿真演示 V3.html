16 / Learn the model

DEDS 原理与事件处理流程

Future Event → CLOCK → Event → State → Interval → Accumulation → Statistic

建议讲解顺序：先在上方完成几个事件，观察“当前事件”的六步讲解；再展开这里的术语和 NETA 流程，最后把状态表、图表与统计公式对应起来。
① DEDS 的对象与术语：定义、本例对应、易混点
② NETA 事件调度：为什么 CLOCK 直接跳到下一时刻
③ FITA 与 NETA：两种时间推进方式如何区别
④ 为什么统计量来自状态区间的面积
⑤ 常见误区与自查方法

给定服务时间 ≠ 已服务时间。服务时间 Si 是输入；只有顾客真正开始服务后，实际忙碌的时间段才进入 busyTime。

排队人数 ≠ 系统内人数。正在接受服务的顾客占用服务台，但不在等待队列中，因此不计入 Q(t)。

只算已离开顾客会漏记等待。终止时仍在队列的顾客已经从到达到 T 持续等待，这一部分同样进入等待面积。

事件发生时先后顺序不可混用。先累计事件前的整个时间区间，再处理同刻服务完成、到达与终止；到 T 后不让队首重新开始服务。

不能把事件点上的 Q 做普通算术平均。每个 Q 值持续的时间不同，平均排队人数必须用 ΣQ(t)Δt / T。

自查两条守恒式。忙时 + 空闲时 = T；进入人数 = 离开人数 + 终止时排队人数 + 终止时服务中人数。
